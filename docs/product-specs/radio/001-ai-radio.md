## 1. 背景与问题

- 现有音乐 App 的推荐趋于同质化：听得多的越推越多，用户陷入「信息茧房」，听歌变成机械的循环播放。
- 歌单式的消费方式把听歌变成了「选择任务」，而不是「被陪伴的体验」。
- 缺少情感与上下文：同一首歌在雨天早晨和晴天傍晚的意义不同，但现有产品几乎不理解这种差别。
- 用户想要的是一个像深夜电台一样、有人陪着、有人讲故事的听歌方式。

## 2. 产品愿景与定位

**一句话定位**：一个运行在 macOS 上、由 LLM 驱动的 AI 主理人私人音乐电台——她了解你今天的天气与心情底色，替你挑歌，并用一段短短的故事把你带进音乐里。

核心价值主张：

1. **无需选择**：不展示歌单，不要求用户挑歌，打开即听。
2. **有故事的音乐**：每首（或每组）歌前有简短口播，讲背景、讲为什么今天推荐给你。
3. **有温度的陪伴**：科幻管家式的主理人，克制、聪明、略带幽默。
4. **常听常新**：在熟悉与新鲜之间动态平衡，打破千篇一律。

设计原则：

- 声音优先：这是一个「听」的产品，界面应尽量轻，不抢注意力。
- 惊喜大于控制：用户让渡选择权，换取被惊喜到的体验。
- 真实优先：故事必须真实可靠，宁可少讲，不可编造。
- 口播有节制：短、准、不打扰，用户随时可以跳过。

## 3. 目标用户与使用场景

**核心用户**：对音乐有一定兴趣、但已听腻自己歌单的人；在 Mac 前工作、学习、睡前等「伴随式」听歌场景的个人用户（本项目即作者本人）。

| 场景 | 描述 | 对产品的要求 |
| --- | --- | --- |
| 早晨开工 | 打开 Mac 即播，主理人问候并带出天气与今日首曲 | 口播短，节奏轻快 |
| 工作专注 | 后台长时间播放 | 口播精简（可配置），音乐为主 |
| 雨天/阴天 | 天气影响情绪 | 选歌与口播语气随天气变化 |
| 睡前 | 安静陪伴 | 语速放缓，曲风舒缓，可定时停止 |

## 4. 核心概念：主理人

主理人是产品的灵魂，既是 DJ，也是策展人，也是管家。

- **身份**：科幻风格的 AI 管家型电台主理人，**温柔女声**（风格参考「钢铁侠的智能管家」类角色：沉稳、礼貌、机智，但语气温柔，冷幽默点到即止）。
- **名称**：**Lyra（天琴）**——取自天琴座（Lyre，音乐之琴），自带科幻与音乐双重意象；备选 Vega（织女星）、Iris。
- **边界**：风格借鉴而不模仿；不克隆任何真实演员的声音，使用原创设定与授权的 TTS 音色。
- **能力**：感知上下文、选歌、讲故事、响应简单点按/快捷键指令（跳过、喜欢、不想听）。

## 5. 功能需求

优先级：P0 = MVP 必须；P1 = 重要，第二阶段；P2 = 可选/探索。

### 5.1 情境感知（P0）

系统在每次开播及切歌时，汇总以下上下文，作为推荐与口播的输入：

- **天气**：当前天气、温度、昼夜、季节（基于 macOS 定位，需授权；可用 WeatherKit 或开放天气接口）。
- **时间**：时段（清晨/午后/深夜）、工作日/周末。
- **用户近期偏好**：最近常听、重复播放、完整听完、跳过、收藏的歌曲/艺人/风格（首选来自 Apple Music；QQ 音乐的数据可得性待验证）。
- **（P1）设备与活动状态**：耳机/扬声器、专注模式、会议中自动静默口播。
- **（P2）日历/心情自述**：用户可选授权，或一句话描述心情。

### 5.2 推荐引擎（P0）

- **无需挑歌**：不提供歌单与未来队列，用户不需要选择；界面呈现当前曲目的歌名，并提供短期的「阅后即焚」历史（见 5.5）。
- **随机但有逻辑**：以「情境 + 偏好」为约束进行随机抽取，而非单纯热门或相似度排序。
- **探索与熟悉配比**：默认约 30% 熟悉的歌、50% 与偏好相邻的新歌、20% 跨风格的意外之选，比例可调。
- **多样性约束**：同艺人/同风格在一段时间内不连续出现；避免短期重复。
- **可解释性**：每次推荐都生成一句「推荐理由」，用于口播（如：因为今天下雨，也因为你最近在听……）。
- **反馈闭环**：喜欢、跳过、听完、重复被作为隐式/显式反馈，影响后续推荐。

### 5.3 主理人口播（P0）

- **内容结构**（总时长建议 15–30 秒，可配置）：
  1. 开场/承接（一两句，结合天气或时间）；
  2. 故事或背景（歌曲、创作、艺人、年代中最有趣的一点）；
  3. 推荐理由（为什么是今天、为什么是你）；
  4. 引出歌曲。
- **口播频率**：默认**每首歌前都讲**；可在设置中改为每 2–3 首一次、仅新歌、或关闭。
- **故事真实性**：故事内容必须基于可检索的可靠资料（如 MusicBrainz、维基、官方访谈、唱片资料）；无可靠资料时，改讲「推荐理由」或情境化陈述，不得编造事实。
- **声音**：温柔女声，云端高质量神经 TTS，温和沉稳、略带科幻感但自然不机械；支持语速、音色的个性化选项。
- **预生成**：因每首都讲，口播脚本与音频必须在上一首播放期间预生成并缓存，保证无缝衔接。

**实现方式（MVP）**：由程序编排整条流程（选曲 → 取资料 → 生成脚本 → TTS → 播放），LLM 只负责撰写口播脚本，不自行调用工具；之后再升级为 Agent 式的工具调用。

**模型选型提示**：GLM-5.3-Flash 于 2026 年 8 月发布，支持 1M 上下文与 Function Calling，但思考模式**不能关闭**，只能用 `reasoning_effort`（low / high / max）调强度，首字延迟可能偏高；口播在上一首播放期间预生成，影响有限，仍需实测（口播这类短文本先试 low）。同系列的 GLM-5.3-FlashX 速度更快，可作备选。它只输出文本，不能发声，TTS 需另配语音服务。

### 5.4 播放编排与混音（P0）

- **口播期间人声突出**：口播开始时音乐渐弱为背景（ducking，降低到约 15–25% 音量），口播结束后音乐渐强回到正常音量。
- **前奏衔接**：口播尽量在歌曲前奏/间奏内收尾，歌曲「正常开始」时不被口播打断。（⚠ 技术方案未实现前奏分析，靠把口播控制在 30 秒内替代；见 [decisions.md](../../decisions.md)。）
- **过渡**：淡入淡出，避免突兀的切换；口播带有轻微的科幻音效作为开场提示（可关闭）。
- **控制**：跳过口播、跳过歌曲、暂停、喜欢、不想听这类歌；支持键盘媒体键、菜单栏与全局快捷键。
- **音量实现**：音乐来自第三方播放器时，通过控制其音量或系统音频实现 ducking，需技术验证（见第 10 节）。
- **后台运行**：菜单栏常驻，后台连续播放。

### 5.5 交互形态（P0 先选一，其余 P1）

| 形态 | 说明 | 优先级 |
| --- | --- | --- |
| 刘海/顶部悬浮岛（类灵动岛） | 位于 MacBook 刘海区域或屏幕顶部居中：收起态显示封面缩略与声波，悬停/点击展开显示歌名、主理人字幕、喜欢/跳过 | P0 |
| 菜单栏常驻 | 菜单栏图标 + 下拉面板，含当前曲目、字幕与基础控制 | P0 |
| 吸顶条 | 屏幕顶部全宽细条，显示当前曲目与声波，点击展开 | P1 |
| 侧边悬浮窗 | 屏幕侧边可折叠悬浮窗，含字幕与基础控制 | P1 |
| 主窗口 | 极简界面：主理人形象/声波动效 + 当前曲目 + 历史入口 | P1 |

**界面要点**：口播时显示实时字幕与声波动效；音乐时显示歌名、艺人、封面；不展示播放队列与未来曲目。macOS 没有系统级的灵动岛，悬浮岛需用自绘悬浮窗实现；目标机型带刘海，悬浮岛从刘海处展开；没有刘海的 Mac（含外接屏）降级为顶部居中的胶囊。

**历史记录（阅后即焚）**：

- 可以查看已播放的歌名、艺人与时间。
- 阅后即焚：历史条目查看后关闭面板即清除；未查看的条目保留 24 小时后自动清除（暂定规则，待确认）。
- 不可导出，不生成歌单；想留下的歌只能点「喜欢」，写入音乐账号的收藏。
- 历史仅存本地。

### 5.6 个性化设置（P1）

- **（P0）模型配置**：云端大模型由你自行配置（API 地址、密钥、模型名），默认推荐 GLM-5.3-Flash（智谱，模型 ID glm-5.3-flash）；TTS 同样走云端、可自行配置；密钥存放在 macOS 钥匙串。
- 口播频率（每首/每 2–3 首/仅新歌/关闭，默认每首）、口播时长、语速、音色。
- 探索度滑杆（偏熟悉 ↔ 偏惊喜）。
- 屏蔽艺人/曲风、「勿扰时段」（只放歌不口播）。
- 语言偏好（中文为主，支持粤语、英文等歌曲）。

### 5.7 记忆与成长（P2）

- 主理人记得与你的「共同经历」（如：上周下雨你听了这首）。
- 周期性小结：本周电台回顾（以故事形式，而非歌单）。

### 5.8 音源接入（P0）

- **Apple Music（首选）**：通过 MusicKit 获取订阅曲库、最近播放与收藏，并控制播放。
- **QQ 音乐（P1）**：官方没有第三方开放接口，但社区已有现成的 MCP server，可做搜索、歌词、播放链接（如 [mcp-music-server](https://glama.ai/mcp/servers/ms3baiqyzw) 支持 QQ/网易云/酷狗，QQ 音乐需扫码登录；[mcp-qqmusic-test-server](https://glama.ai/mcp/servers/@Samge0/mcp-qqmusic-test-server) 仅有搜索，定位为测试用）。它们底层都依赖非官方的 qqmusic-api-python，接口一变就可能失效。
- **QQ 音乐的播放路径（已选 B）**：通过接口取播放链接，由本 App 自带播放器播放，淡入淡出与 ducking 完全可控。这属于非官方用法，有版权与服务条款风险，仅限个人自用；会员歌曲需要你自己的 QQ 音乐登录凭证，凭证只存本地。接口失效时降级到 Apple Music。
- **网络爬取（兜底，P2）**：仅在上述音源找不到歌曲时使用，限个人自用、不分发。
- **统一抽象**：音源层提供搜索、播放、暂停、音量、最近播放的统一接口，推荐引擎不感知具体音源。
- **跨源匹配**：按歌名 + 艺人匹配同一首歌（有 ISRC 时优先）。

## 6. 核心体验流程

1. **开播**：用户点击/快捷键唤起 → 系统获取天气、时间与偏好 → 生成首条口播与首曲。
2. **口播**：音乐低音量铺底 → 主理人用 15–30 秒讲述故事与推荐理由 → 音乐渐强。
3. **播放**：歌曲正常播放；期间用户可喜欢/跳过。
4. **衔接**：播放期间后台预生成下一首的口播与选曲；每首歌前都有口播（可配置）。
5. **结束**：用户暂停/定时关闭；主理人可有一句简短收尾。

## 7. 人设与对话风格规范

**语气关键词**：温柔、沉稳、礼貌、精确、轻微冷幽默、科技感、不油腻。

写作规则：

- 称呼用户：「先生/女士」或自定义昵称（用户可选，默认中性称呼）。
- 每段口播不超过 120 字，句子短，留有停顿。
- 适度使用系统化措辞（如「已为您分析今日天气与您近期的聆听轨迹」），但不堆砌术语。
- 禁止：夸张的营销腔、重复口头禅、过度自我介绍、编造事实。
- 保持分寸：不在用户疑似情绪低落时调侃。

示例口播（示意，非最终文案）：

> 早上好。外面正下着小雨，气压偏低，适合把节奏放慢一点。根据您最近的聆听记录，我为您挑了一首您没听过的歌——它是一位歌手在搬家前一晚，对着空房间录下的小样。请放松，我们开始。

## 8. 非功能需求

- **延迟**：点击到出声 ≤ 3 秒（首次可由缓存口播或开场音效衔接）。
- **衔接无缝**：歌曲与口播切换无明显空白（< 0.5 秒）。
- **稳定性**：菜单栏常驻，连续后台播放 ≥ 8 小时不中断；休眠/唤醒后可自动恢复。
- **成本**：每首都讲，每首需要一次 LLM + TTS；通过预生成、缓存与精简上下文并提供每日调用上限；实际成本取决于你配置的云端模型。
- **无障碍**：字幕、大字号、键盘操作支持。
- **多语言**：口播语言与歌曲语言可不同，默认跟随系统语言。

## 9. 数据与隐私

- 定位、听歌记录等仅在授权后使用，授权可单项关闭；天气只需城市级粗略位置。
- 数据本地存储，不经自建服务器；调用你自行配置的云端 LLM/TTS 时仅发送必要上下文（曲目、天气、偏好摘要）；API 密钥存放在 macOS 钥匙串，不明文落盘。
- 联网检索故事资料时只发送曲名与艺人，不发送位置与听歌历史。
- 播放历史阅后即焚，不做长期留存；用户可一键重置个性化数据。
- 字幕与口播不外显精确位置等敏感信息。

## 10. 关键风险与技术难点

| 风险 | 说明 | 初步应对 |
| --- | --- | --- |
| 音源接入与版权 | Apple Music 有官方 MusicKit；QQ 音乐无官方开放接口；爬取音源存在版权与服务条款风险 | Apple Music 为主，QQ 音乐为辅，爬取仅作兜底，限个人自用、不分发 |
| 混音与 ducking 可行性 | 第三方播放器的音量难以精细控制，口播叠加可能受限 | 阶段 0 先做技术验证；备选为口播独立音轨 + 系统/应用音量协同 |
| 故事真实性（幻觉） | LLM 可能编造歌曲背景 | 检索增强（RAG）+ 来源校验；无来源则降级为推荐理由 |
| 没有系统级灵动岛 | macOS 不提供灵动岛能力 | 用自绘悬浮窗在刘海/顶部居中实现；无刘海机型降级为胶囊 |
| 每首都讲的疲劳与成本 | 重复口播可能打扰，LLM + TTS 成本累积 | 口播长度与句式多样化、可配置频率、预生成与缓存 |
| TTS 质感 | 机械感会破坏沉浸 | 选用高质量神经语音，预生成并做 EQ/轻混响后处理 |
| 角色版权 | 模仿影视角色存在 IP 与声音权风险 | 原创人设 Lyra 与音色，仅借鉴风格 |

## 11. MVP 范围与里程碑建议

**MVP（目标：验证「故事 + 随机推荐」是否真的更好听）**

- 平台：macOS 单端，含刘海/顶部悬浮岛与菜单栏。
- 音源：Apple Music（MusicKit）。
- 情境：天气 + 时段 + 近期偏好。
- 推荐：基础的「熟悉/相邻/意外」三档抽取，带推荐理由。
- 口播：温柔女声 Lyra，每首都讲（可配置），15–30 秒，预生成，含 ducking。
- 设置：口播频率、静音口播、屏蔽艺人；历史记录阅后即焚。

**里程碑（建议）**

1. 第 0 阶段：技术验证（Apple Music 播放与音量控制、ducking、TTS 选型、QQ 音乐接入方案）。
2. 第 1 阶段：核心闭环（选曲 + 口播 + 混音），自用迭代。
3. 第 2 阶段：悬浮岛与菜单栏体验打磨，历史阅后即焚。
4. 第 3 阶段：QQ 音乐等更多音源、个性化与记忆能力。

## 12. 成功指标

- **自评听感**：试用一周后，主观评分「比原来的歌单更不乏味」。
- **口播保留率**：口播被完整听完（未跳过）的比例，目标 ≥ 70%。
- **新歌发现**：每周被喜欢/收藏的新歌数量。
- **使用黏性**：日均使用时长、连续使用天数。
- **故事准确性**：抽检口播中的事实，无明显错误。

## 13. 已确认决策与待确认问题

**已确认**

- 「AI 原声」= AI 原生：把 LLM 集成为产品功能（选曲理由、故事口播、对话），不含 AI 生成音乐。
- 平台：macOS，目标机型带刘海。
- 音源：Apple Music、QQ 音乐，网络爬取作兜底；QQ 音乐的播放走路径 B（取播放链接，由本 App 播放）。
- 歌名与历史记录可见，历史阅后即焚（查看后关闭即清除、未查看保留 24 小时）。
- 主理人：温柔女声，名称 Lyra（天琴），如想换名随时可改。
- 口播：默认每首都讲，可配置。
- 模型：云端大模型与 TTS 均由你自行配置，口播脚本默认推荐 GLM-5.3-Flash。
- 实现方式：MVP 由程序编排流程，LLM 只写口播脚本。
- 故事资料：允许联网检索（维基、MusicBrainz 等）。
- 项目性质：个人项目。
